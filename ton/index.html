Why it is built carefully

Payment code on a blockchain does not get a second chance. A transaction that has been sent cannot be reversed, and there is no bank, processor or chargeback to fall back on. If the code sends funds to the wrong address, credits an order twice, or accepts a payment that is not real, the money is gone permanently.

The business that handles customer money is legally responsible for it. A bug in the payment flow becomes that business's problem, with its customers and with the law.

For that reason this work is built carefully by someone who has done it before and knows where these systems fail. It is not assembled quickly by someone who is meeting the failure modes for the first time. Some of the points that get checked on every project:

  • fake jettons sent from a jetton wallet not tied to the real USDT master
  • missing, reused or malformed payment comments
  • bounced messages counted as successful payments
  • the same transaction processed twice after a restart
  • orders released before the transaction is confirmed
  • wrong address format (bounceable vs non-bounceable)
